# SRS — contorell 權限比對管理系統  v0.1

> 本文件承接 [`CoreMain.md`](../CoreMain.md) 的專案主題與範圍主軸，是開發、測試、驗收的單一真相來源。
> 三維度 Exit Criteria 由本文件推導（見 [`待修改.md`](../待修改.md)）。

---

## 1. 專案概述與背景

- **要解決的問題 / 為誰而做**：
  企業 IT 管理者在做權限稽核時，AD 是人員的權威來源，但實際權限散落在各個系統（ERP、VPN、檔案伺服器、SaaS）。目前只能靠人工匯出 Excel 逐筆核對，耗時且容易漏掉「離職者帳號還活著」這類高風險缺口。
- **商業目標**：
  把一次權限稽核從「數天的人工比對」縮短到「數分鐘的自動比對 + 人工標註」，並留下可追溯的稽核軌跡。
- **範圍邊界**：見 `CoreMain.md`「範圍主軸」。核心界線：**本系統唯讀，不做權限異動寫回**。

## 2. 整體描述

- **產品定位**：內部使用的權限盤點與差異比對工具（唯讀稽核輔助），非 IAM 平台。
- **使用者輪廓（Persona）**：見 [`docs/UX-Design.md`](UX-Design.md)。主要為「IT 管理者／資安稽核人員」。
- **營運環境**：企業內網，Docker 部署（Linux 容器），連線至內網 AD 網域控制站。
- **相依系統**：
  - Active Directory（Windows Server 2016 / 2019 / 2022 / 2025）— 必要
  - 外部系統 REST API — 選用，由管理者設定
  - PostgreSQL 16 — 資料儲存
- **前提假設與限制**：
  - 假設 AD 有一組**唯讀服務帳號**可執行 LDAP 查詢（最小權限原則）。
  - 假設外部系統提供可回傳帳號清單的 REST API（JSON）。
  - 限制：不處理跨樹系（cross-forest）信任的複雜情境，v1 僅支援單一網域。

## 4. 非功能需求（NFR）

| 編號 | 類別 | 可量化指標 |
|---|---|---|
| **NFR-01** | 效能 | 抓取 5,000 名使用者的 AD 群組（含巢狀展開）於 60 秒內完成；比對兩份各 5,000 筆名單於 5 秒內完成 |
| **NFR-02** | 效能 | 比對結果頁面 P95 回應 < 500ms（分頁，每頁 50 筆） |
| **NFR-03** | 安全 | 對照 `secure-coding-practices.md` / OWASP Top 10:2025；SAST/SCA Critical/High = 0 |
| **NFR-04** | 安全 | **所有 AD 連線一律使用 LDAPS (636) 或 StartTLS**，禁止明文 389 bind；憑證驗證預設開啟 |
| **NFR-05** | 安全 | AD 服務帳號密碼、API 金鑰**一律加密儲存**（不得明文入庫、不得寫入版控），採用 envelope encryption |
| **NFR-06** | 安全 | AD 服務帳號採**最小權限**：僅需 Domain Users 等級的讀取權，不需 Domain Admin |
| **NFR-07** | 安全 | 所有 LDAP 查詢參數**必須經過 LDAP 特殊字元轉義**，防止 LDAP Injection (CWE-90) |
| **NFR-08** | 相容性 | 支援 Windows Server **2016 / 2019 / 2022 / 2025** AD DS，詳見第 5.1 節相容性矩陣 |
| **NFR-09** | 可靠度 | 外部 API 抓取失敗時不影響既有快照；具備 timeout（30s）與重試（3 次，指數退避） |
| **NFR-10** | 可維護 | 新增一種資料來源型態不需修改比對引擎（依賴反轉，介面隔離） |
| **NFR-11** | 可用性 | 介面達 WCAG 2.1 AA；SUS ≥ 68；主要流程任務完成率 ≥ 90% |
| **NFR-12** | 擴充性 | 資料來源設定為資料驅動（存於 DB），新增外部系統不需重新部署 |

## 5. 外部介面需求

### 5.1 AD / LDAP 介面 — **Windows Server 版本相容性矩陣**

這是本專案最關鍵的相容性風險。各版本預設安全策略不同，連線程式必須**自動協商**而非寫死。

| 特性 | WS 2016 | WS 2019 | WS 2022 | WS 2025 |
|---|---|---|---|---|
| **LDAP Signing 預設** | 未強制（可協商） | 未強制（可協商） | 未強制（可協商） | **預設要求 Signing**（新部署） |
| **Channel Binding 預設** | Never（停用） | Never（停用） | Never（停用） | **When Supported** |
| **TLS 1.3 for LDAPS** | ❌ 不支援 | ❌ 不支援 | ❌ 不支援 | ✅ 支援（預設啟用） |
| **TLS 1.2** | ✅ | ✅ | ✅ | ✅ |
| **AES SHA-256/384 簽章** | ❌ | ❌ | ❌ | ✅ 新增 |
| **RC4** | 可用 | 可用 | 可用 | **已棄用** |
| **分頁查詢上限 MaxPageSize** | 1000 | 1000 | 1000 | 1000 |
| **巢狀群組查詢 (LDAP_MATCHING_RULE_IN_CHAIN, OID 1.2.840.113556.1.4.1941)** | ✅ | ✅ | ✅ | ✅ |

**由矩陣推導出的實作要求（IR）**：

| 編號 | 實作要求 | 理由 |
|---|---|---|
| **IR-01** | 連線一律走 **LDAPS/StartTLS**，並支援 **SASL bind 搭配 signing/sealing** | WS2025 新部署預設要求 signing，純 simple bind over 389 會被拒絕 |
| **IR-02** | TLS 版本**自動協商**（允許 1.2 與 1.3），不得寫死單一版本 | WS2016~2022 只有 TLS 1.2；WS2025 支援 1.3。寫死任一版本都會在另一端失敗 |
| **IR-03** | **一律使用分頁查詢（paged search）**，page size ≤ 1000 | AD 硬性限制單次回傳 1000 筆，不分頁會靜默截斷資料，導致比對結果錯誤 |
| **IR-04** | 巢狀群組展開提供**兩種策略**：`LDAP_MATCHING_RULE_IN_CHAIN`（單次查詢，DC 端運算，較慢）與**遞迴展開**（多次查詢，應用端運算），可設定切換 | IN_CHAIN 在大型群組上效能差；需依環境選擇。兩者所有支援版本皆可用 |
| **IR-05** | 不得使用 RC4 相關加密選項 | WS2025 已棄用，會導致連線失敗 |
| **IR-06** | 連線設定需可指定「是否驗證伺服器憑證」與「自訂 CA 憑證」 | 企業內網常用自簽 CA；但預設必須為**驗證開啟**（安全預設） |
| **IR-07** | 啟動時執行**連線能力探測**，記錄實際協商到的 TLS 版本與 signing 狀態，並顯示於 UI | 讓管理者能自我診斷相容性問題，而非看到一句 "bind failed" |

**AD 讀取屬性**：`sAMAccountName`、`userPrincipalName`、`displayName`、`mail`、`distinguishedName`、`objectSid`、`userAccountControl`（判斷停用）、`whenCreated`、`whenChanged`、`memberOf`、`member`。

> 停用判斷：`userAccountControl` 的 bit 1（值 2, ACCOUNTDISABLE）為 1 即為停用。

### 5.2 外部系統 API 介面（通用連接器）

管理者可設定：
- **端點**：HTTP(S) URL、方法（GET/POST）、額外 headers
- **驗證方式**：None / API Key（header 或 query）/ Bearer Token / Basic Auth
- **回應解析**：JSON path 指向帳號陣列（如 `$.data.users`）
- **欄位對應**：哪個 JSON 欄位對應「帳號」「顯示名稱」「Email」「啟用狀態」
- **分頁**：無分頁 / offset-limit / page-size / cursor

### 5.3 Excel / CSV 匯入介面

- 接受 `.xlsx`、`.csv`；上限 10MB / 50,000 列
- 上傳後顯示前 10 列預覽，由管理者指定欄位對應
- 編碼自動偵測（UTF-8 / UTF-8-BOM / Big5）

### 5.4 使用者介面

Web 介面（響應式，桌面優先）。詳見 [`docs/UX-Design.md`](UX-Design.md)。

| **AC-09** | FR-09 | 填寫的自訂欄位可儲存、重新載入後仍存在、可隨匯出一併輸出 |
| **AC-10** | FR-10 | 可新增/編輯/停用自訂欄位定義；支援文字、下拉、日期三種型別 |
| **AC-11** | FR-11 | 快照可保存並列出；「這次 vs 上次」比對能正確標示新增／移除的成員 |
| **AC-12** | FR-12 | 匯出檔案可用 Excel 開啟，含所有欄位與自訂欄位，中文不亂碼 |
| **AC-13** | FR-13 | AD 帳密可成功登入；未登入存取任何 API 皆回 401；一般使用者無法存取管理者專屬功能（回 403）；**登入用帳密不得被儲存**（人工檢查 DB 與 log） |
| **AC-13b** | FR-13b | AD 不可達時，本地管理員仍可登入；本地密碼以 argon2 雜湊儲存；兩種管道的登入失敗訊息一致（防帳號列舉）；連續失敗觸發節流 |
| **AC-14** | FR-14 | 抓取、比對、修改標註、修改連線設定皆產生稽核紀錄（操作者/時間/對象/動作） |

## 限制與已知風險

1. **無真實 AD 測試環境**：使用者尚未提供正式 AD，將以 Docker Samba AD DC 建立模擬環境。模擬環境與真實 WS2025 的 signing 行為可能有差異，**WS2025 相容性需在使用者實際環境二次驗證**（列為已知風險 R-01）。
2. v1 僅支援單一網域，不支援跨樹系信任。
3. 唯讀系統，不做權限異動寫回（設計決策，非缺陷）。
