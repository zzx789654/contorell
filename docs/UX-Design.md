## 一、Discover（探索）

### Persona

**P1 — 王經理，IT 系統管理員（主要使用者，80% 使用量）**
- 40 歲，管理 AD 與 8 套內部系統，每季被要求交一次權限稽核報告。
- 技術能力：熟 AD、看得懂 LDAP filter，但不寫程式。
- 目標：快速找出「不該還有權限的人」，並在報告上說明每一筆的處置。
- 使用情境：季度稽核前一週，坐在辦公室桌機前連續作業 2-3 小時。

**P2 — 陳稽核，資安/內稽人員（次要使用者，20%）**
- 35 歲，不碰 AD 操作，只看結果與軌跡。
- 目標：確認稽核有被執行、每筆差異有人負責、有紀錄可查。
- 使用情境：偶爾登入查看報表與稽核軌跡，或收 Excel。

### 痛點清單（對照主題）

| 編號 | 痛點 | 現況 | 對應需求 |
|---|---|---|---|
| PP-01 | 人工比對 Excel 極耗時，5000 人要比好幾天 | VLOOKUP 手工核對 | FR-06 |
| PP-02 | 巢狀群組展不開，常常漏人 | 手動一層層點開 ADUC | FR-03 |
| PP-03 | 離職者在外部系統還活著，最高風險卻最難發現 | 靠印象抽查 | FR-08 |
| PP-04 | 比對完的處置決策記在另一個 Excel，下次找不到 | 散落各處 | FR-09 |
| PP-05 | 稽核問「上次到這次改了什麼」答不出來 | 沒有快照 | FR-11 |
| PP-06 | AD 連不上時只看到一句 error，不知道是憑證還是帳密問題 | 求助原廠 | AC-01, IR-07 |

## 二、Define（定義）

### 問題陳述

> 王經理需要一種方法，能把 AD 群組成員與其他系統的帳號名單**自動比對出差異**，並**在同一個地方記錄每筆差異的處置說明**，因為目前的人工 Excel 比對耗時數天、會漏掉巢狀群組成員，且處置紀錄散落各處無法追溯。

### User Journey（主要流程 — P1 季度稽核）

```
[1] 登入
     │
[2] 設定資料來源（首次才做，之後重用）
     │   ├─ AD 連線設定 → 測試連線（顯示 TLS/signing 狀態 ← 解 PP-06）
     │   ├─ API 來源設定（URL/驗證/欄位對應）
     │   └─ Excel 上傳（欄位對應）
     │
[3] 建立比對 ★核心動作★
     │   選來源 A ──┐
     │             ├─→ [按下比對]
     │   選來源 B ──┘
     │
[4] 檢視結果（四種狀態，預設先顯示「高風險」）
     │   ├─ 🔴 僅存在於外部系統（孤兒帳號）← 解 PP-03
     │   ├─ 🟠 AD 已停用但外部仍啟用（最高風險）
     │   ├─ 🟡 僅存在於 AD（外部缺漏）
     │   └─ 🟢 相符
     │
[5] 逐筆標註（自訂欄位）← 解 PP-04
     │   處理狀態 / 負責人 / 描述說明
     │
[6] 匯出 Excel 交報告
     │
[7] （下一季）用快照比對「這次 vs 上次」← 解 PP-05
```

**關鍵設計決策**：步驟 [3] 是核心動作，必須在登入後**一頁內**可達（首頁即為「新增比對」）。步驟 [2] 是一次性設定，收在設定區，不擋在主流程上。
> 依據：Nielsen #7「彈性與使用效率」— 高頻動作路徑最短；Hick's Law — 首頁只給一個主要選擇。

### 資訊架構（IA）

```
contorell
├── 🏠 比對（首頁，預設著陸頁）
│   ├── 新增比對（選 A / 選 B / 執行）★主要動作
│   ├── 比對結果檢視（篩選 / 標註 / 匯出）
│   └── 歷史比對紀錄
├── 📦 資料來源
│   ├── AD 連線設定（含測試連線診斷）
│   ├── API 來源清單（新增/編輯/測試）
│   └── Excel 匯入
├── 📸 快照
│   └── 快照清單 / 快照間比對
├── ⚙️ 設定
│   ├── 自訂欄位定義
│   └── 使用者與權限
└── 📋 稽核軌跡（P2 主要入口）
```

> 四個核心概念（來源→快照→比對→標註）直接對應到導覽結構，**不多不少**——呼應 CoreMain「不再增加第五個概念」。

### 功能優先順序（MoSCoW）

| 優先 | 功能 |
|---|---|
| **Must** | FR-01 AD連線、FR-03 群組成員抓取(含巢狀)、FR-06 比對、FR-07 四狀態、FR-09 自訂欄位填寫、FR-13 登入授權 |
| **Should** | FR-02 群組瀏覽、FR-04 API來源、FR-05 Excel匯入、FR-08 離職稽核標記、FR-12 匯出 |
| **Could** | FR-10 自訂欄位定義、FR-11 快照比對、FR-14 稽核軌跡 |
| **Won't (v1)** | 權限異動寫回、簽核工作流、跨樹系支援 |

## 三、設計原則對照（每個決策的依據）

| 設計決策 | 依據原則 | 驗證指標 |
|---|---|---|
| 首頁即「新增比對」 | Nielsen #7 彈性與效率；Hick's Law | 主要任務完成率 ≥ 90%、步驟數 ≤ 6 |
| 四狀態用顏色+圖示+文字三重編碼 | WCAG 1.4.1（不單靠顏色傳達資訊）；格式塔相似性 | a11y 稽核無 Critical 違規 |
| 結果預設排序「高風險優先」 | Nielsen #6 辨識勝於回想；Serial Position Effect | 使用者能在 30 秒內指出最高風險項 |
| 連線測試顯示 TLS/signing 診斷 | Nielsen #9 協助辨識與診斷錯誤 | 錯誤訊息可行動性測試通過（PP-06） |
| 三種來源共用同一設定介面骨架 | Jakob's Law（一致心智模型）；格式塔相似性 | 學會一種即會其他兩種 |
| 長時間抓取顯示進度與可取消 | Nielsen #1 系統狀態可見性 | 無「以為當掉」的可用性卡點 |
| 自訂欄位就地編輯（inline edit） | Fitts's Law（縮短操作距離）；減少 context switch | 標註 20 筆的耗時 ≤ 5 分鐘 |

## 四、可用性 Exit Criteria（供 QA 階段 3 驗證）

**質化**
- 可用性測試 5 位受測者，**無阻斷性（Critical）卡點**
- 啟發式評估（Nielsen 十大）**無 Critical/High 問題**
- a11y 稽核（axe + Lighthouse）**無 Critical 違規**，達 WCAG 2.1 AA

**量化**
- 核心任務（建立比對→檢視→標註→匯出）**任務完成率 ≥ 90%**
- 核心任務**錯誤率 ≤ 10%**
- **SUS ≥ 68**
- 首次使用者完成核心任務 **≤ 10 分鐘**（無教學）

**UI 狀態完備性（每個資料畫面都必須具備）**
- loading / empty / error / 無權限 / 極長字串（DN 可達 255 字元）/ 極大資料量（5000 筆）
